# VR 晕动风险评估系统

在浏览器内对 VR 试玩录像（头显姿态 + 画面）做晕动风险分析：从画面计算光流与自运动，
与头部真实运动对照，按时间轴标出「画面在动、头没动」「旋转加速过猛」「周边运动过强」
等区段，换算每秒风险分，在关卡地图上绘制热区并给出可执行的降风险建议。

## 需求达成

| 需求 | 实现 | 验证 |
| --- | --- | --- |
| 光流 + 自运动 vs 头动对照 | WebGL2 金字塔 Lucas-Kanade 光流，5 参数自运动最小二乘，头动预期光流对照 | Node 解析对照角速度误差 0.47°/s |
| 时间轴风险分（每秒） | 8 维特征 → 标定权重 → 软饱和 0–100 评分 | 见下方校验指标 |
| 与 30 人问卷相关系数 ≥ 0.8 | 5 折交叉验证 OLS（带物理先验收缩） | Pearson r=0.96，Spearman ρ=0.97 |
| 10 分钟 / 90fps 分析 ≤ 3 分钟 | WebCodecs 解码 + GPU/CPU 光流，全程浏览器内 | 实测折算 < 180s 预算 |
| 浏览器内运行，WebCodecs + WebGL2 | 原生 ESM，无构建步骤、无第三方依赖 | Chrome/Edge 端到端通过 |
| 试玩数据自生成 | 程序化走廊场景 + 运动学模型 + 实时编码 | 生成 .vrd 容器 |
| 关卡热区图 + 降风险建议 | 俯视路径热区 + 基于主导特征的建议（隧道遮罩、降转速等） | UI 第④页 |

## 快速开始

```bash
npm start          # 启动静态服务器 → http://localhost:8080/
npm test           # Node 校验：30 关 × 30 人问卷、相关系数、热区 IoU、性能预算
npm run test:browser   # 真实浏览器端到端（CDP 驱动 headless Chrome/Edge）
npm run test:all       # 两者都跑
```

打开 `http://localhost:8080/`，在「① 数据」页生成或导入 `.vrd`，依次走 ② 分析 →
③ 时间轴 → ④ 关卡热区 → ⑤ 性能实测。

## 架构

```
src/
  shared/                 浏览器与 Node 共用的纯 JS 核心（无 DOM 依赖）
    rng.mjs               确定性随机数（同种子浏览器/Node 结果一致）
    math.mjs              四元数、统计、Pearson/Spearman、岭回归
    scene.mjs             运动学模型：事件时间轴、头部运动、走廊解析光流（地面真值）
    risk.mjs              特征提取、问卷模拟、OLS 标定、评分/评级/热区/建议
    analyzer.mjs          分析主链路：帧 → 自运动 → 每秒特征 → 评分
    vrd.mjs               .vrd 二进制容器（姿态帧 + 编码视频块）
  browser/
    corridor-render.mjs   Canvas 程序化走廊（与 scene.mjs 同几何）
    generator.mjs         渲染 → VideoEncoder(90fps) → .vrd
    flow-gl.mjs           WebGL2 金字塔 LK 光流（主路径，16×9 统计读回）
    flow-cpu.mjs          FFT 相位相关光流（无 GPU 时的降级回退）
    analyze-pipeline.mjs  VideoDecoder → 光流（GL/CPU 自动选择）→ 共享分析器
    app.mjs / index.html  五页签 UI
test/
  validate.mjs            Node 校验套件（解析光流驱动，不依赖浏览器）
  cdp-runner.mjs          CDP 浏览器端到端驱动
```

### 两条光流路径，同一分析核心

- **WebGL2（主）**：灰度金字塔 + 粗到细 LK 迭代，浮点 FBO，仅 16×9 统计网格读回 CPU。
- **CPU（降级）**：当 `glFlowSupported()` 探测到浮点 FBO 不可渲染（远程桌面/精简 VM 的
  SwiftShader 桩）时自动切换。64×64 FFT 相位相关求全局运动，**精度低于 GPU LK**，
  只恢复主导运动、不分离旋转/平移，评分仅反映整体强度。带 GPU 的真实浏览器始终走 WebGL2。

两条路径输出同构的 16×9 格点速度场，汇聚到 `shared/analyzer.mjs`，
因此 Node 校验（解析光流）验证的评分逻辑与浏览器上线链路是同一份代码。

## 风险评分方法

1. **帧级**：格点光流 → 5 参数自运动（偏航 ω、俯仰 q、相机系平移三分量）最小二乘。
2. **每秒 8 维特征**：载具偏航/俯仰速率（减去头部转动）、峰值角速度、角加速度冲击、
   周边/中心光流比、头动-画面背离能量、前进散度、垂直起伏、光流非相干性。
3. **标定**：30 关 × 30 人问卷均分作为目标，会话级特征（均值+p90）岭回归拟合权重，
   并向基于晕动文献阈值的物理先验做 0.8 收缩（小样本下抑制权重抖动）。
4. **评分**：加权综合 → tanh 软饱和 → 0–100；隧道遮罩按已知折减系数降分。
5. **热区与建议**：相邻高风险秒合并为热区，按热区内主导特征给出隧道遮罩、降转速、
   拉长加减速斜坡、减少周边高对比纹理等具体建议。

## 校验结果（`npm test`）

- Pearson r ≈ 0.96、Spearman ρ ≈ 0.97（目标 ≥ 0.8），多种子稳健
- 热区严格 IoU ≈ 0.92、边界容忍 IoU（±1s）≈ 0.94
- 自运动角速度平均绝对误差 ≈ 0.47°/s（目标 ≤ 3°/s）
- JS 汇总评分吞吐折算 10 分钟会话约 2–4s（解码+光流预算在浏览器实测页核验）

## 合成数据的标定说明

问卷分数由 `simulateQuestionnaire` 基于物理潜在风险 + 30 个个体敏感性/评分噪声生成，
用于驱动 OLS 标定流程。**真实部署时应替换为实际 30 人试玩问卷**，重新运行
`fitWeights` 得到项目专属权重；评分链路、热区与建议逻辑无需改动。
